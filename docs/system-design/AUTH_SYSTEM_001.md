## 1. 결론 요약

- 저장소에 서버·DB·인증이 **없었으므로**, 홈페이지 확장이 가능한 최소 구성으로 **Node.js + Express 5 + SQLite + Argon2id** 인증 서버를 `server/` 폴더에 새로 추가했다.
- 기존 게임(`src/web-mvp/`), React 시뮬(`src/`), GitHub Pages 배포는 **변경하지 않았다.**
- 유료 서버·관리형 서비스는 생성하지 않았다. 운영 배포는 호스팅을 선택한 뒤 별도로 진행한다(10장).

## 3. 기술 선택과 이유

| 구성 요소 | 선택 | 선택 이유 | 검토한 대안 |
|---|---|---|---|
| 실행 환경 | Node.js 22.9+ | 기존 프로젝트가 npm 기반 → 새 언어·도구 불필요 | — |
| 웹 서버 | Express 5 | 가장 널리 쓰이는 Node 웹 프레임워크. 화면·API 추가가 쉬움 | Fastify(성능↑, 학습 자료↓) |
| DB | SQLite (`better-sqlite3`) | **무료**, 별도 DB 서버 불필요, 파일 1개로 백업 쉬움. UNIQUE·CHECK·외래키·트랜잭션 지원 | PostgreSQL(서버 여러 대·대규모 시 전환) |
| 비밀번호 해시 | Argon2id (`argon2`) | OWASP 권장 1순위 알고리즘. 일방향(복호화 불가) | bcrypt |
| 세션 | DB 세션 + HttpOnly 쿠키 | 로그아웃·강제 만료가 즉시 반영됨 | JWT(즉시 무효화 어려움) |
| 보안 헤더 | `helmet` | CSP·클릭재킹 방지 등 표준 헤더 일괄 적용 | 수동 설정 |
| 요청 제한 | `express-rate-limit` | 비밀번호 대입·가입 남용 차단 | — |
| 화면 | HTML + CSS + 순수 JS | 기존 `web-mvp`와 같은 방식, 빌드 과정 불필요 | React(현 단계엔 과함) |

**관리형 인증(Supabase·Firebase 등)을 쓰지 않은 이유**: 외부 계정·프로젝트 생성이 필요하고 무료 한도·요금 정책이 수시로 바뀌므로 사용자 결정 사항으로 남겼다. 회원 테이블·세션 구조가 단순해 추후 전환이 가능하다.

## 4. 기능 명세

| 기능 | 동작 |
|---|---|
| 회원가입 `/signup` | 화면·서버 이중 검증 → 이메일 중복 확인 → Argon2id 해시 저장 → **자동 로그인 후 `/dashboard` 이동** |
| 로그인 `/login` | 이메일 정규화 후 조회 → 해시 검증 → 새 세션 발급 → `/dashboard` 이동 |
| 로그인 유지 | 쿠키 + DB 세션. **7일간 미접속 시 만료**, 접속 시 자동 연장, **최초 로그인 30일 후 무조건 만료** |
| 로그아웃 | DB 세션 삭제 + 쿠키 삭제 → `/login`에 "로그아웃되었습니다." 안내 |
| 접근 제어 | `/dashboard`는 서버가 세션 확인 후에만 제공. 로그인 상태로 `/login`·`/signup` 접근 시 대시보드로 이동 |
| 세션 만료 안내 | 만료된 쿠키로 대시보드 접근 시 `/login`에 "로그인 유지 시간이 지났습니다" 안내 |

### 화면 공통 동작

- 오류·안내는 팝업 없이 **화면 안**에 표시(입력란 아래 + 상단 안내 영역)
- 오류가 나도 **입력값 유지**(로그인 실패 시 비밀번호는 선택 상태로 두어 바로 재입력 가능)
- 처리 중에는 버튼에 **스피너 + "처리 중…"** 표시, 처리 중 재클릭·엔터 **중복 요청 차단**
- 비밀번호 **표시/숨김** 버튼(필드별), 가입 화면은 비밀번호 조건 체크리스트 실시간 표시
- 접근성: `<label>` 연결, `aria-invalid`·`aria-describedby`로 오류 연결, `role="alert"/"status"` 안내, 첫 오류 칸으로 포커스 이동, 논리적 Tab 순서, 모바일 키보드 유형(`inputmode`)·자동완성(`autocomplete`) 지정
- 반응형(모바일 390px ~ PC), 다크 모드 자동 대응

## 6. 보안 설계

| 위협 | 대응 |
|---|---|
| DB 유출 시 비밀번호 노출 | Argon2id(메모리 19MiB·반복 2·병렬 1, OWASP 최소 권장) 해시만 저장. DB CHECK 제약으로 해시 형식 외 저장 차단. 설정 상향 시 다음 로그인 때 자동 재해시 |
| DB 유출 시 세션 탈취 | 세션 토큰(32바이트 난수)은 쿠키에만 두고 DB에는 SHA-256 해시만 저장 |
| 중복·동시 가입 | 사전 조회 + **DB UNIQUE 제약**(최종 차단). 동시 5건 가입 시 1건만 성공 테스트로 검증 |
| 비밀번호 대입 공격 | 같은 IP+이메일 로그인 실패 15분 10회 초과 시 차단, IP당 인증 요청 15분 100회, 가입 15분 10회 |
| 가입 여부 탐색 | 로그인 실패 문구 통일("이메일 또는 비밀번호가 올바르지 않습니다"), 없는 이메일도 같은 해시 연산 수행(응답 시간 균일화) |
| 세션 고정 | 로그인·가입 때마다 새 세션 발급, 이전 세션 폐기 |
| 쿠키 탈취(XSS) | `HttpOnly`, CSP(`script-src 'self'`, 인라인 스크립트 금지), 회원 이름 HTML 이스케이프 |
| CSRF | `SameSite=Lax` 쿠키 + 상태 변경 요청의 `Origin`/`Sec-Fetch-Site` 검사 + JSON 요청만 허용 |
| 중간자 공격 | 운영 모드에서 `Secure` + `__Host-` 쿠키, HSTS, HTTPS 업그레이드 |
| 뒤로 가기 캐시 | 화면·API `Cache-Control: no-store`, 대시보드 복원 시 로그인 상태 재확인 |
| 과대 요청 | JSON 본문 10KB 제한 |

## 7. DB 스키마 (SQLite)

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT NOT NULL CHECK (length(trim(name)) > 0),
  email         TEXT NOT NULL UNIQUE CHECK (email = lower(trim(email))),
  password_hash TEXT NOT NULL CHECK (password_hash LIKE '$argon2id$%'),
  created_at    TEXT NOT NULL,   -- ISO 8601
  updated_at    TEXT NOT NULL
) STRICT;

CREATE TABLE sessions (
  id         TEXT PRIMARY KEY,   -- SHA-256(세션 토큰)
  user_id    INTEGER NOT NULL REFERENCES users (id) ON DELETE CASCADE,
  created_at INTEGER NOT NULL,   -- epoch ms
  expires_at INTEGER NOT NULL
) STRICT;
```

- 스키마 변경은 `server/src/db.js`의 `MIGRATIONS` 배열에 순서대로 추가하고, 적용 여부는 `PRAGMA user_version`으로 관리한다.
- 만료 세션은 서버 시작 시와 1시간마다 자동 삭제한다.

## 10. 운영 배포 가이드 (요약)

1. Node.js 22.9 이상을 실행할 수 있고 디스크가 유지되는 호스팅(VPS 또는 영구 볼륨 지원 PaaS)을 선택한다.
2. `server/`에서 `npm ci --omit=dev` 후 `npm start`로 실행한다.
3. 환경 변수: `NODE_ENV=production`, `APP_ORIGIN=https://실제주소`, `DATABASE_PATH=영구경로/app.db`, 프록시 뒤라면 `TRUST_PROXY=1`.
4. HTTPS 인증서를 적용한다(없으면 운영 모드 쿠키가 전송되지 않아 로그인이 유지되지 않음).
5. 서버를 여러 대로 늘릴 경우 요청 제한 저장소(현재 메모리)와 DB(SQLite → PostgreSQL) 전환을 검토한다.
