# 보안 요구사항 및 적용 현황 (SECURITY)

## 1. 인증·세션
- 비밀번호는 **평문 저장 금지** — `crypto.scrypt`(salt별 해시, `scrypt$salt$hash`)로 저장, 비교는 `timingSafeEqual`.
- 세션 토큰은 32바이트 랜덤, **httpOnly + SameSite=Strict** 쿠키로만 전달(JS에서 접근 불가 → XSS 토큰 탈취 완화).
- 세션 만료(8시간), 로그아웃/정지 시 세션 폐기. 매 요청 세션 유효성·계정 상태 재검증.
- **로그인 실패 5회 → 15분 잠금**, 실패/성공 모두 감사 로그 기록.

## 2. 접근제어 (핵심)
- 인증되지 않은 사용자의 보호 API 접근 차단(401). 미로그인 시 내부 화면 데이터는 전부 API에서 막힘.
- **역할 기반 + 세분화 권한**을 서버 라우트에서 강제(`requirePermission`). 화면 버튼 숨김에 의존하지 않음.
- 업무일지/개인정보는 라우트 권한 + 핸들러 내 **공개범위·부서·목적 판정**으로 이중 통제.
- 개인정보 원문은 `member.pii.read` + **열람 목적 필수**, 모든 열람을 `personal_data_access_logs`에 기록.
- 권한 거부 시 `access.denied` 감사 로그 적재.

## 3. 입력·인젝션 대응
- 모든 DB 접근은 **파라미터 바인딩 prepared statement** → SQL Injection 방지(문자열 결합 쿼리 없음).
- 입력 검증 헬퍼(`str/oneOf`)로 길이·허용값 검증, 잘못된 JSON은 400(한국어 안내).
- 프론트는 출력 시 **`esc()`로 HTML 이스케이프** → 저장형 XSS 방지.
- **CSP**(`script-src 'self'`)로 인라인 스크립트 차단, `X-Content-Type-Options`, `X-Frame-Options: DENY` 적용.
- 정적 파일은 경로 정규화 후 public 밖 접근 차단(경로 추측/디렉터리 탈출 방지).

## 4. CSRF
- 인증에 httpOnly 쿠키 사용 + **SameSite=Strict** → 크로스사이트 자동전송 차단으로 CSRF 완화.
- 상태 변경은 GET이 아닌 POST/PATCH/PUT/DELETE로만. (프로덕션 전환 시 이중 제출 토큰/Origin 검증 추가 권장 — 미완료 목록)

## 5. 개인정보 보호
- 목록에서 이름·연락처·생년월일·이메일·주소 **마스킹**, 권한자만 목적 입력 후 원문 열람.
- 고위험 정보(주민등록번호·계좌·건강정보)는 **MVP 미수집**. 샘플은 전부 가상 데이터.
- 필요 최소 항목만 수집. 소프트 삭제로 복구 가능성 확보.

## 6. 비밀 관리
- 서비스 키·DB 비밀번호는 저장소에 커밋하지 않음. `.env.example`만 제공, `.env`는 `.gitignore`.
- (프로덕션) `SUPABASE_SERVICE_ROLE_KEY`는 **클라이언트에 절대 노출 금지**, 서버에서만 사용.

## 7. 파일 업로드 (프로덕션 예정) — 대응 방안 문서화
파일함은 MVP 미구현. 구현 시 적용할 방침:
- 확장자 화이트리스트 + 크기 제한 + MIME 검증, 원본 파일명 대신 서버 생성 키 저장(경로 추측 차단).
- 다운로드는 **서명 URL(짧은 만료) + 권한 재검증**. 악성 파일은 미리보기 격리/백신 연동 검토.

## 8. 백업·복구
- 참조 MVP: SQLite 파일+WAL 정기 복사. 프로덕션: Supabase 자동 백업/PITR.
- 장애 시 최신 백업 복원 → 마이그레이션 재적용 → 시드는 운영 데이터에 실행 금지.

## 9. 알려진 보안 미완료 항목
- CSRF 이중 제출 토큰/Origin 화이트리스트(현재 SameSite=Strict에 의존).
- 세션 회전(refresh)·다중기기 세션 관리 UI, 비밀번호 정책(복잡도·만료) 강화.
- Rate limiting(로그인 외 API), 감사 로그 무결성(해시체인/외부적재).
- 파일 업로드 보안 일체(미구현 기능).
