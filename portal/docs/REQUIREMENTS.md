# 요구사항 정리 (REQUIREMENTS)

## 1. MVP 범위 (이번 구현)
- 초기 관리자 설정, 로그인/로그아웃, 세션 유지, 로그인 실패 잠금, 계정 정지
- 역할 6종 + 세분화 권한 18종, 서버·DB 단계 권한 강제, 역할·사용자별 권한 조정
- 사용자 관리(생성/수정/정지/삭제/개별권한), 부서 관리(계층·부서장), 직책
- 권한별 대시보드
- 업무일지: 작성/조회/수정(낙관적 잠금)/승인/소프트삭제, 상태·우선순위·공개범위, 필터·검색
- 조합원/임직원 인적사항: 마스킹 목록, 목적 입력 후 원문 열람, 열람이력, 등록/수정
- 감사 로그(활동/개인정보 열람이력) 읽기 전용, 사용량·저장공간 조회

## 2. 후속(향후) 범위
공용 파일함(버전관리·서명URL), 업무 매뉴얼(버전·승인), 업무 칸반/캘린더/체크리스트/반복업무,
공지사항, 알림센터, 개인정보 수정요청 승인, 엑셀 가져오기/내보내기, 실시간(웹소켓),
외부문서(엑셀/한글/PDF) 잠금·연동. → `ROADMAP_UNDONE.md`

## 3. 사용자 역할
최고관리자 / 개인정보관리자 / 부서장 / 부서원 / 감사·열람 / 일반 조합원.
관리자가 역할 추가·권한 조정 가능(확장형).

## 4. 권한표
`PERMISSIONS.md` 참조(역할×권한 매트릭스 + 공개범위 + 개인정보 규칙).

## 5. 데이터 구조 / 화면 구조
`DATABASE.md` / 화면: 로그인·초기관리자·대시보드·업무일지·조합원인적사항·사용자관리·
부서관리·역할권한·감사로그·사용량·내정보(구현). 파일함·매뉴얼·칸반 등은 후속.

## 6. 보안 요구사항
`SECURITY.md` 참조.

## 7. 요구사항 충돌 시 판단 원칙과 근거
- **"실제 Supabase 사용" vs "실행 가능·검증 가능한 MVP"** — 실습 환경에 라이브 Supabase
  자격증명이 없어, 지금 즉시 "실제 로그인·서버 저장·새로고침 유지·권한 강제"를 **증명**하려면
  프로비저닝이 필요 없는 서버 DB가 필요. → 무의존성 Node+SQLite로 구현하되 스키마·권한을
  PostgreSQL/RLS로 이식 가능하게 설계(안전성·이식성 우선). 근거: `README.md` 3장.
- **부서장/부서원의 개인정보 접근** — 요구사항이 "원칙적 불가 / 별도 권한 시에만"으로 명시 →
  기본 권한에서 제외하고 개별 권한 부여로만 허용(가장 안전한 최소권한 원칙).
- **동시편집 수준** — 문자단위 공동편집은 MVP 필수 아님 → 낙관적 잠금 + 충돌 감지로 안전하게 처리.
