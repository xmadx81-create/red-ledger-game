# 관리자 가이드 (ADMIN_GUIDE)

## 초기 관리자 생성
관리자 계정이 하나도 없을 때 최초 접속하면 **초기 관리자 설정** 화면이 뜹니다.
이름·이메일·비밀번호(8자 이상)로 최고관리자를 1회 생성합니다. 이후에는 이 화면이 나오지 않습니다.

## 사용자 관리 (`user.manage`)
- **추가**: 이름·이메일·역할·부서·초기 비밀번호. 생성된 사용자는 다음 로그인 시 비밀번호 변경 권장 플래그가 붙습니다.
- **수정**: 이름·역할·부서·상태 변경, 비밀번호 재설정(비우면 유지).
- **정지**: 즉시 로그인 차단 + **활성 세션 강제 종료**. 본인 계정은 정지/삭제 불가.
- **삭제**: 소프트 삭제(복구 가능, 이메일 재사용 가능).
- **개별 권한**: 특정 사용자에게 역할 기본권한 위에 세부 권한을 추가 부여할 수 있습니다
  (예: 특정 부서장에게 `member.read` 부여).

## 부서 관리 (`dept.manage`)
부서 추가/수정, 부서장 지정, 상·하위 부서 구조. 부서는 소프트 비활성화 가능.
예시 부서(전략기획실·석유사업부·가맹관리부·미디어홍보부·감사실·전산개발)는 샘플이며 자유롭게 변경.

## 역할·권한 관리 (`role.manage`)
- 각 역할의 세분화 권한을 체크박스로 조정 → **권한 저장**. 변경은 즉시 모든 API에 반영됩니다.
- 최고관리자 권한은 안전을 위해 잠겨 있습니다.
- 새 역할을 추가해 조직에 맞게 확장할 수 있습니다.

## 개인정보 감독
- **감사 로그 > 개인정보 열람이력**에서 누가·언제·누구 정보를·어떤 목적으로 열람했는지 확인.
- 개인정보관리자(`privacy_officer`)는 인적사항 원문 열람·수정과 열람이력 확인이 가능하되,
  시스템 설정·사용자 권한 변경은 불가합니다.

## 사용량·비용
**사용량** 화면에서 사용자수·MAU·DB 사용량·무료한도 사용률을 확인. 비용 산정은 `COST_ESTIMATE.md`.

## 운영 주의사항
- 시드 스크립트(`portal:seed`)와 테스트 비밀번호(`Test1234!`)는 **개발 전용**. 운영 배포 전 반드시 변경.
- 감사 로그는 수정/삭제 불가(무결성). 데이터 삭제는 소프트 삭제 우선.
- 백업(`EBTS_DB_PATH` 파일)을 정기적으로 확보하세요.
